# デザイン・文言のガイド（見せ方の決まり）

人から受けた指摘を、次から自分で防げるように一般化した決まり。ページ・記事・サービスページ・図を作るとき、直すときに守る。品質管理部は、見た目の確認でこのガイドも見る。

- 対象：サイトのすべてのページ（コーポレート・アキヤド・記事）。
- 指摘を受けたら、ここに1行で足す（どのページで何が起きたかの例も添える）。
- 基本は CLAUDE.md の「基本姿勢」（読み手にとって価値のある情報を、スッキリ見せる）。

## 1. 見出し

- **見出しに「」を使わない。** 行頭の「が半角ぶん下がって、行頭が段々に見える（例：買取プランの見出し「古くて売れない」と…）。強調したい言葉は、色やマーカー（`<em>`）で見せる。
- **見出しも本文と同じく、行末まで詰めて自然に折り返す（3章）。** 最後の行に1〜2文字だけがはみ出すときは、文を短くするか、`<br>` で意図した位置に切る（例：「宿の運営はアキヤドがすべて／行います」→「改修から宿の運営まで、すべてアキヤドが行います」）。
- **見出しはラベルではなく、言い切りにする**（「選ばれる理由」ではなく「売るだけでなく、家を残す道も一緒に比べます」）。見出しを拾い読みしただけで話が通じるように。
- **意味の伝わらない造語・業界の言い回しを見出しに使わない**（例：「宿の目で査定」→「宿として活かせるなら買い取ります」）。

## 2. 数字の見せ方

- **数字そのものを大きく、前置き（約・最大・最低保証など）と単位は小さく。** 「最大6倍」なら「6」が大きく、「最大」「倍」は小さい（サービスページの「放っておくと」のタイル、実績の数字のカード）。
- **費用がかからないことは「0円」ではなく「無料」と書く**（相談・試算・査定など）。
- **数字には条件を添える**（期間・時点・何を基準にした数字か・保証しないこと）。注記は数字の下の小さい文字でよい。
- 公開しない方針の数字（例：下田の宿の円の実額）は、割合・倍率で見せる。公開している数字を組み合わせて、非公開の金額が逆算できる見せ方もしない。

## 3. 文章と改行

**改行の考え方（人の方針 2026-11-13。これまでの「言葉の切れ目で折る」「1文ごとに改行する」などの決まりは、すべてこれに置き換えた）**

- **改行は全部、右詰め（ふつうの組版）。** 本文・見出し・カード・リード・表のマスのどれも、行末まで詰めて折り返す。言葉の途中で折れてもよい（ブラウザの禁則処理で「、」「。」や閉じかっこが行頭に来ること、開きかっこが行末に残ることは起きない）。文節や1文ごとの改行、両端揃えはしない。
- **途中で切らないのは、数字と単位（「約3,188万人」「2027年3月31日」「2つ」）、ハイフンでつないだ英単語（「Wi-Fi」）、会社名（「合同会社RIVIA&CO.」）だけ**（`tools/build_parts/common.py` の `phrase_breaks`）。英単語は、ブラウザがもともと途中で折らない。
- **最後の行が2〜3文字になるのは許す。ただし、並んだ項目（同じ親の中の続く段落・リストの項目・カード）で続けて起きたら直す**（`js/main.js` の `fitTails` が、後の項目の最後の5文字をまとめて前の行から送る）。それでも気になる所は、文字数を整える。
- **行の区切りを手で決めるのは、トップのコンセプト文のような短いコピーだけ**（`lines_html` にリストで渡す。1要素＝1行）。文字列で渡した文は、右まで詰めて流す。
- **要点・カード・吹き出しは短く書く**（改行の見た目は、仕組みより「文を短くする」ことで決まる。`docs/seo/benchmark-2026-11-12.md`）。
- **丸い印（円の中の数字・「Q」「R」・矢印）の文字は、円の真ん中に置く**（人の指摘 2026-11-07）。フォントは上下の余白が違うので、`display: grid` の中央寄せだけでは文字が下にずれる（iPhone のフォントで目立つ）。文字の印は `display: block; text-align: center; align-content: center; text-box: trim-both cap alphabetic; letter-spacing: 0; line-height: 1;`（大文字の高さで真ん中に置く。字間は横のずれになるので 0）。矢印・チェックなどの記号は、文字ではなく線（border・SVG）で描く。点検は `node tools/check/badge_center.js`（円の中の文字のずれを、画面を撮って測る）。
- **点検**：`node tools/check/line_quality.js`（全ページをスマホ幅で開き、はみ出し・行末の開きかっこ・短い最後の行の連続を数える。どれも0件にする）と `node tools/check/badge_center.js`。改行・文字組みを変えたら必ず流す。
- **同じ字・同じ意味の言葉を重ねない、何をしてどうなったかが伝わる文にする**（例：「見直して立て直しました」→「1泊の料金を9,800円から18,500円に上げると、売上が増え、清掃は月7回前後に減りました」）。
- **お客様に向けた言葉は、敬意のある言い方にする**（「支えます」→「支援します」。開業プランのリード）。
- **スマホは文字数を減らす。** スマホで1画面に文字を詰めない。図が同じことを見せているなら、スマホ版の文章は要点だけの短い版にしてよい（PC版と別に書く。例：TOPのコンセプト）。

- **サービスページは、文字より先に図と写真で伝える。** 誰が何をして、お金がどう流れるかは「しくみの図」で見せ、写真を添える。同じ形のカードが縦に3枚以上続くときは、スマホでは横にスワイプにする（「放っておくと」のタイル・プラン）。
- **横スワイプのカードには、枚数と「横にスワイプ」の案内を必ず付ける。** 1枚目だけを見て「これで全部」と思われないように、各カードに「1 / 3」、カードの上に「全3枚・横にスワイプで続きへ →」を出す（`figures.compare` の3列以上は自動で付く。民泊の備品の「買う順番の3段階」で指摘 2026-11-02）。同じ中身を、図の直前に箇条書きでも繰り返さない。
- **図やカードの箇条書きが「一部の例」なら、例だと分かるようにする。** 見出しに「（例）」「（件数の多い例）」などを付け、最後に「ほか、◯◯など」の1行を入れ、全体がどこで見られるかを注に書く（民泊の備品の「備品の仕分け」で指摘 2026-11-05）。
- **計算式は、スマホでも横に並べる。** 縦に積むと式に見えない。長い言葉は式に入れず、短い言葉の式にして、説明は式の下に添える（買取価格の決まり方）。
- **実績の数字は、どの物件の数字かと「一例」であることを明記する**（他の物件も運営しているため。サービスページの「運営する宿の一例」）。
- **事例（インタビュー）記事は、本人が話し続けるだけにしない。編集部（聞き手）の質問を、話題が変わるところごとに入れる**（目安：吹き出し1〜2個ごとに1問。サイクリストの宿の事例で指摘）。質問は `<p class="talk__q">`（`tools/articles_interviews.py` では `_Q("…")`）で書く。build.py が、アキヤドのマークを顔にした「編集部」の吹き出しにして、対話の形で見せる。質問は次の答えを引き出すだけにして、答えにない事実・数字を質問に書かない。
- **補足・断り・出典・時点は、文の中に（　）で入れず、段落の下の ※注記（`<p class="table-note">※ …</p>`）にする。** 「（80万円に許可費用や消防設備が含まれるかは確認していません）」のような（　）書きは、スマホで行数を増やし、本文の結論が読みにくくなる（人の指摘 2026-11-01）。（　）に残してよいのは、用語の短い言い換えだけ。
- **対談の枠（`.talk`）の中には、顔写真と吹き出し以外を入れない。** 注記などが入ると、吹き出しが1文字幅に潰れて縦書きのようになる（別荘DIYの事例。`seo_check` がエラーにする）。

## 4. 色と強調

- **濃い背景（緑の帯など）の上の強調は、白い太字だけにする。** 黒い文字や、背景と同系色のマーカーは見えにくい（サービスページの緑の帯の「無理のない計画」）。
- マーカー（`strong.hl`）は、白や淡い背景の上だけで使う。読み手にとって価値のある・惹かれる言葉に引く（創業者の手紙）。段落の最後にマーカーを置くと改行が不自然になりやすいので、文の途中の言葉に引く。

## 5. レイアウト

- **見出しと、その下の図・表・カードの間には余白をとる**（目安：PC 36px／スマホ 28px 以上）。見出しにくっつけない。
- **奇数個の項目を2列に並べて、最後の1つだけを余らせない。** 1列にするか、列の数と項目の数を合わせる（サービスページの悩みのリスト）。
- **カードが1枚だけのときは、中央に寄せる**（2列の枠に1枚だけ置いて、右に中途半端な余白を作らない。買取プランのプランのカード）。
- **丸い写真・丸い枠は、幅と高さを明示して正円にする。** `aspect-ratio` だけだと、iPhone の Safari で縦長の楕円になることがある（会社概要の創業者の写真と点線の輪）。
- 画像を差し替えるときは、URL に版番号（`?v=中身のハッシュ`）を付ける（画像は30日キャッシュされるため、同じ名前で差し替えると古い画像が出続ける）。

## 6. 表

- **比べるものは表にする。** スマホで選択肢ごとのカードにすると、縦に見比べられずわかりにくい。
- **比較表は、アキヤド（自社）の強みが伝わる見せ方にする。** 違いが出る項目（列）を選び、アキヤドの行を色で目立たせる。ただし、事実と違う評価は付けない（できないことを◎にしない）。
- **比較は、ぱっと見でわかるように記号で見せる。** 各マスに評価マーク（◎とてもよい／○よい／△負担・注意／×なし）を色つきで大きく出し、言葉は小さく添える。表の上に凡例を置く。文字だけの表は読まれにくい（サービスページの「ほかの方法と、ここが違います」）。評価は読み手から見た目安として「目安です」と注記する。
- **評価の記号（◎○△×）は文字ではなく図形で描く。** 文字だとフォントによって丸の中心からずれる。マスの文言の行数が違っても記号の高さがそろうよう、マスは上揃えにする。
- 表のマスは短い言葉にする（文章は表の下の注記か、本文へ）。
- **表の項目名に3つ以上を「・」で並べ、1行に収まらないものは、1つずつ改行した箇条書きにする**（「鍵・／チェックイン／・防犯」のように「・」が行頭・行末に残るため。人の指摘 2026-11-06）。表の1列目の9文字以上のものは、`tools/build.py` の `label_lists` が自動で「・鍵／・チェックイン／・防犯」にする。
- **サービスページの比較表は、選択肢を横（列）に、比べること（初期費用・手間・収入など）を縦（行）に並べる。** スマホは1列目（比べること）を止めたまま左右にスライドでき、次の列が少し見えるようにして、表の上に「表は左右にスライドできます →」と添える（人の指摘 2026-10-24）。
- 文字が中心の表で、スマホで文字が小さくなりすぎるなら、表を横にスクロールさせる（1列目＝項目の名前は固定し、「表は横にスクロールできます →」と添える）。文字は 14px を下回らせない。

## 7. フォームと CTA

- **申し込みは「無料で相談する」か「資料をもらう」の2択から始める。** 診断・質問をはさんで段階を増やさない。資料を選んだら、ご相談カテゴリを「サービス資料の請求」にする（`tools/forms/Code.gs` が資料の請求と判定し、自動返信に資料を付ける）。
- **上から目線の言い回しを使わない**（「断ってもかまいません」→「内容を見てから、進めるかどうかを決めていただけます」）。
- ページの途中・最後のボタンは、同じフォームへ移す（資料のボタンは、資料を選んだ状態で開く）。
- **ファイルの添付は、点線の添付の枠で見せる**（`tools/build.py` の `file_box()`。小さいフォームは `cls="file--compact"`）。ブラウザの素の部品（「Choose Files」「ファイルを選択」）をそのまま出さない（人の指摘 2026-10-30）。

## 8. 確認の手順（作ったら・直したら）

1. `python3 tools/build.py` のあと、変えたページを **幅390px・360px・1280px** で撮って、自分の目で見る（見出しの改行・数字の大きさ・表・カードの中の折り返し・余白）。
2. `python3 tools/seo_check.py`（エラー0）と `node tools/check/site_check.js`（重大0）を通す。
   改行・文言を変えたときは `node tools/check/linebreak_samples.js` も通す（NG 0。「変化」が出たら、意図した変化か `--shots` の画像を人に見せる）。
3. 本番で古い表示が残るときは、キャッシュ（画像は30日、CSS・JS は版番号つき）を疑う。
4. **改行の指摘を受けたら、ルール文を足す前に「見本」を足す**（人の方針 2026-11-07）：指摘された文を `tools/check/linebreak_samples.json` に入れ（ページ・要素・幅）、直したあとの形を記録する。人が「これで良い」と言ったら `status` を `approved` にする。ルール文は、同じ種類の指摘が2回目になったときだけ一般化して3章に書く。ルールを足すときは、3章の既存のルールと矛盾しないか（どちらを優先するか）を必ず書く。
   - 点検の画像は、Web フォント（Noto Sans JP など）を読み込んで撮る（`site_check`・`short_lines`・`linebreak_samples` は既定で読み込む）。フォントを止めると代わりのフォントで組まれ、人が見る画面と改行の位置が変わる。

## 2. 共通の設計

| 項目 | 設計 |
|---|---|
| 記事の型 | 結論 → 概要表 → 費用・収支の表 → インタビュー → うまくいかなかったこと → 解説 → チェックリスト → Q&A → メッセージ → 取材情報 → 問い合わせ |
| 見出し | 質問形・数字入りにする（「いくら？」「どう取った？」）。起承転結の言葉は使わない |
| 構造化データ | Article（著者・公開日・更新日）とBreadcrumbListを実装。FAQ構造化データは優先度を下げ、Q&Aは本文として表示する |
| 内部リンク | 各事例 ⇔ ハブ（事例一覧）⇔ ガイド記事（空き家の民泊活用・旅館業の許可・収支シミュレーション）を相互にリンク |
| 画像 | 改修前後・内観の写真に、alt文を付ける。数字は画像にせず、テキストの表で載せる |
| 問い合わせ導線 | 記事末のCTAに加え、解説パートの直後にも、ガイド記事への誘導を置く |
| 計測 | 記事ごとのCTAクリック率、問い合わせ件数、事例からの遷移先を見る |

## 3. 公開前に必ず確認すること

- **取材から約1年が経っています**（取材は2025年9月〜12月）。可能なら、各オーナーに現在の数字（月商・純利益・営業の状況）を確認し、更新日と共に反映します。難しければ、「数字は取材時点」と明記したまま公開します。
- **補助金・公庫融資・旅館業の許可の制度は変わる場合があります。** 2026年時点の最新情報を、公庫・自治体・保健所の公式情報で確認し、解説パートの記述を見直します。
- **営業形態の記載。** 各記事の概要表に「旅館業許可を取得し、通年営業」と書いてあります。オーナーごとに実際の形態と合っているか、確認してください。
- **【要差し替え】【要追記】の枠。** 問い合わせURL、関連記事リンク、公開日・更新日を埋めます。
- **匿名化の確認。** 場所や建物の組み合わせで、取材先が特定されないか、最終確認します。

## 4. 公開後の運用

- 半年ごとに、数字（月商・純利益・稼働）を更新し、「運営◯ヶ月目」の追記を検討する。
- 検索順位が10〜30位の事例を、見出しとQ&Aの追加でリライトする。
- 新しい取材ができたら、ハブの一覧表に追加する。

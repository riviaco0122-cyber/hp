## 1. ひとことで言うと

**落ち着いた「です・ます」で、結論を先に、数字には出典をつけ、言い切れないことは言い切らない。**
読者（空き家オーナー・宿の開業検討者・観光事業者）の不安に寄り添いながらも、あおらず、売り込まない。「自ら宿を運営する当事者」が、現場の目線で淡々と整理して伝える文体です。

## 2. 文体ルール

### 2-1. 文末

- 本文は **です・ます調** で統一する（28記事すべてがそうなっている）。
- よく使う文末:
  - 事実: 「〜です」「〜あります」「〜なっています」
  - 判断の目安: 「〜が大切です」「〜が欠かせません」「〜のが安全です」「〜のが確実です」「〜が近道です」
  - 断定を避ける: 「〜場合があります」「〜ことがあります」「〜可能性があります」「〜傾向があります」「〜ケースは少なくありません」
  - 行動を促す: 「〜しましょう」（手順・注意点の締めで使う。記事内で多用しすぎない）
  - 読者に考えてもらう: 「〜してみてはいかがでしょうか」（まとめで1回まで。既存記事では1件のみ）
- **「！」は記事本文で使わない**（記事28本で 0 件）。ゲストのレビューの引用だけは原文のまま。
- 体言止めは、見出し・箇条書き・表・コピー（Mission など）に限る。本文の段落では使わない。

### 2-2. 1文の長さ・段落

- 1文は **30〜60字が目安**。長くても80字程度で区切る（既存記事を読んだうえでの目安。字数を機械的に数えたものではない）。
- 1段落は 2〜3文。段落の最初の文で結論を言う。
- 見出しの直後の1〜2文で、その見出しの問いに答えきる（`docs/seo/playbook.md` 2章）。
- 並べて比べるものは表に、手順は番号付きリストにする。

### 2-3. 漢字とかなの使い分け（詳細は `glossary.md`）

- ひらがなにする語: こと／とき／ください／できる／さまざま／たとえば／〜てもよい・〜ばよい（補助的な「よい」）
- 漢字にする語: 分かる／一つ／良い（「良いレビュー」など、質が良い意味のとき）／届出（名詞）
- 数字は算用数字。大きな数は「約900万戸」「約3,687万人」「8.1兆円」のように3桁区切り＋「約」を付ける。パーセントは半角「%」。

### 2-4. 専門用語の言い換え方

既存記事には、次の3つの型がある。新しい記事もこの型で書く。

1. **日本語の説明 →（用語）**: 「予約が宿泊日のどのくらい前に入るか（リードタイム）」「稼働率（OCC）」「客室単価（ADR）」
2. **用語（日本語の説明）**: 「RevPAR（販売可能な1室あたりの売上）」「住宅宿泊事業法（民泊新法）」
3. **定義文で言い切る**: 「関係人口とは、移住した定住人口でも、観光に来た交流人口でもない、地域と多様に関わる人々のことです。」（AIO 向け。`playbook.md` 3章）

- 初出で必ず補足し、2回目以降は短い方を使ってよい。
- 法律名は初出を正式名称にする（例: 「住宅宿泊事業法（民泊新法）」「旅館業法（簡易宿所）」）。
- 個人のお客様向けの文脈（空き家再生事業・開業支援事業に関わる記事）は「暮らしの言葉」で書く（site-spec 5章の方針）。例: 「経営指標」→「変わること」、「投資回収期間」→「元が取れるまでの期間」。

### 2-5. 読者への呼びかけ方

- **「あなた」「皆さん」は使わない**（記事28本で 0 件）。主語を省くか、「〜という方」「〜という場合でも」と状況で呼ぶ。
  - 例: 「『遠方に住んでいて自分では運営できない』という場合でも、〜方法があります。」
- 読者が実際に口にしそうな言葉を「」で引用して、悩みに寄り添う。
  - 例: 「『実家は地方にあり、自分は都市部に住んでいる』『兄弟の誰も住む予定がない』」
- 自社の呼び方: 記事本文は「RIVIA&CO.」、見出しや短い表記は「RIVIA」。「弊社」は使わない（サービスページの FAQ にだけある）。「私たち」は About のコピーだけで、記事では使わない。
- 相談への誘導は記事の最後に一度だけ、控えめに。
  - 例: 「『うちの空き家でもできるのか』という段階から、お気軽にご相談ください。」

### 2-6. 構成上のくせ（RIVIA らしさ）

- 「一方で、」で、メリットの裏の注意点や、別の見方を必ず示す。
- 「大切なのは、〜ことです。」でまとめる。
- 数字は「出典 → 数字 → 意味」の順で書く: 「総務省『令和5年住宅・土地統計調査』によると、〜は約900万戸で〜」
- 試算や例を示すときは「説明のための仮定」と明記する。
- 限界・向かないケースも正直に書く（例: 一人で1泊するだけなら、ホテルの方が選ばれやすい）。
- `<strong>` での強調は結論の一句だけ。1段落に1か所程度。
- まとめの見出しは「まとめ：〜」の形で、結論を一文で示す（例: 「まとめ：制度選びは『目的』と『物件』で決まる」）。

## 5. 書く前・書いた後のチェック

- [ ] です・ます調で、記事本文に「！」がない
- [ ] 各見出しの直後で結論を言っている
- [ ] 1文がおおむね60字以内に収まっている（80字を超える文は分ける）
- [ ] 専門用語は初出で説明している
- [ ] 「あなた」を使っていない
- [ ] 数字に出典がある。試算は「仮定」と明記している
- [ ] 「一方で」などで、注意点や向かないケースも書いている
- [ ] RIVIA の体験談は `experience.md` にあるものだけ
- [ ] `glossary.md` の統一表記と `ng.md` を守っている

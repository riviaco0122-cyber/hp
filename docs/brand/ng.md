# 書いてはいけないこと（ng）

作成: 2026-10-10 ブランド学習係（初版・人の確認待ち）

材料: `docs/site-spec.md`（トーン＆マナー・除外要素・プランの注記）、`docs/seo/playbook.md`（採点基準・人の確認が必要なもの）、`CLAUDE.md`（絶対のルール）、既存のページ・記事。

迷ったら「Values 01: 自ら宿を運営し、現場で確かめたことだけを提案する」に立ち返る。

---

## 1. 誇大表現・断定

| 避ける表現 | 代わりに | 理由 |
|---|---|---|
| 必ず儲かる／確実に稼げる／絶対に成功する | 「〜できる可能性があります」「〜が見込める場合があります」 | 収益は立地・建物・運営で大きく変わる（`minpaku-investment-yield.html`） |
| 高利回り保証／利回り〇%を保証 | 「保守的な前提で試算し〜」「契約の形によって異なります」 | サービスページでも利回りは「契約の形によって異なります」と書いている（`service-partnership.html` FAQ） |
| 誰でも簡単に開業できる／手間ゼロ | 「〜を任せる方法もあります」 | 法令・改修・運営の手間は実際にある（`akiya-inherited-house-to-inn.html` の比較表） |
| No.1／日本一／業界初／最高の／唯一の | 使わない | 根拠を示せない |
| 自己資金ゼロで開業できる（補助金があるから） | 「補助金は原則として後払いで、採択されないこともあります」 | `small-inn-subsidies.html`、`inn-startup-funding.html` |
| 観光地でなくても必ず宿になる | 「観光地でなくても、収益物件になり得ます」 | サイトの言い方は「なり得ます」まで（`index.html` 相談CTA） |
| どんな空き家でも宿にできる | 「構造が健全であれば、改修で再生できるケースは少なくありません」 | `akiya-inherited-house-to-inn.html` |

## 2. 事実・実績の捏造

- **`experience.md` にない RIVIA の実績・数値・事例・失敗談を書かない。**（`CLAUDE.md` 絶対のルール2）
  - 例: 「当社が運営する宿の稼働率は80%」「これまで100件以上のご相談」「多数の運営実績」
- 運営施設の数・名前を書かない（NODE Shimoda 以外はサイトにない）。NODE Shimoda を紹介するときは「運営施設の一例」と添え、唯一の施設や全実績のように書かない（site-spec 3章）。
- NODE Shimoda の評価（★4.88・51件）は掲載時点の値。時点を添え、勝手に新しい数字にしない。
- **ゲストのレビューを作らない・書き換えない。** 原文のまま引用する（site-spec 2章「実際のレビューを原文のまま入れたときだけ表示」）。
- 出典のない数値を書かない。公的資料の数値は資料名を書く（playbook 2章）。
- 試算・計算例は「説明のための仮定」と明記し、実績のように見せない（`airdna-revenue-simulation.html` の書き方）。
- 架空の「オーナー様の声」「お客様の事例」を作らない。お悩みの例を書くときは「よくある状況」「〜という声」として一般化し、RIVIA に寄せられた声のようには書かない（`experience.md` で確認できたものを除く）。
- 他者の発信（YouTube・X など）を使うときは、発信者名・URL を明記して要約する（playbook 3章）。RIVIA の体験談のように書かない。

## 3. 断定できない法律・税金・補助金・消防の解釈

間違えると読者に損害が出る分野。PR の「人の確認が必要な点」に必ず書き出す（playbook 6章）。

| 避ける表現 | 代わりに |
|---|---|
| 「この物件なら許可が取れます」「この地域なら民泊OKです」 | 「用途地域や自治体の条例によって異なります。物件を取得する前に、保健所・消防署・建築の担当部署へ事前相談するのが安全です」 |
| 「少し貸すだけなら届出は不要です」 | 「宿泊料を受け取って不特定の人を泊める場合は、原則として届出か許可が必要です」 |
| 「〜すれば節税になります」「必ず3,000万円控除が使えます」 | 「一定の条件を満たすと〜」「詳しくは税務署や税理士にご確認ください」 |
| 「この補助金は必ず採択されます」「〇〇補助金で上限〇万円もらえます」（年度を書かない） | 「制度の名称・上限額・補助率は年度や公募回ごとに変わります。必ず最新の公募要領を確認してください」 |
| 「消防設備はこれだけで足ります」 | 「建物の使い方や規模によって必要な設備が変わります。図面を持って管轄の消防署に相談するのが確実です」 |
| 法律の条文や運用の、独自の解釈 | 公的機関の資料（観光庁・厚生労働省・国土交通省・国税庁・総務省消防庁など）の範囲で書く |

- 「原則として」「〜場合があります」「自治体によって異なります」を、正確さのために使う（あいまいにするためではない）。
- 記事の最後に「本記事の数値・制度は公開日時点で公表されている資料にもとづきます」の注記を入れる（全記事共通）。
- 個別の法律・税務の相談に答えるような書き方をしない（RIVIA は法律・税の専門家ではない。監修者がいる場合を除く）。

## 4. 不安をあおる書き方

| 避ける表現 | 代わりに |
|---|---|
| 「放置すると大変なことになります」「手遅れになる前に」「今すぐ」 | 「放置期間が長くなるほど建物の傷みが進み、選択肢が狭まっていく点にも注意が必要です」 |
| 「固定資産税が6倍になります！」 | 「勧告を受けると住宅用地特例の対象から外れ、土地の固定資産税が大きく増える可能性があります」（`akiya-inherited-house-to-inn.html`） |
| 「今が最後のチャンス」「乗り遅れると損」 | 使わない |
| 期限を強調して決断を急がせる | 期限は事実として書き、判断の材料を示す（`akiya-3000man-deduction.html`「期限内に『売る・活かす』の方針を決める」） |
| 相続・家族・思い出に関わる悩みを茶化す、責める | 「判断を先送りにしたまま時間が経ってしまうケースが少なくありません」のように、責めずに状況として書く |

## 5. 競合・他者の批判

- 他社・他の管理会社・予約サイト・データサービスの**名指しの批判をしない**。
- 「他の管理会社はずさん」「大手は高いだけ」のような、比較相手を下げる書き方をしない。比較は条件・特徴・費用の考え方など、事実で書く（`ota-vs-direct-booking.html`「OTAは『入口』、自社予約は『関係づくり』」のように、役割の違いとして書く）。
- ビジネスホテルや他業態を否定しない。向き不向きとして書く（`shizuoka-yaizu-akiya-inn.html`「一人で1泊するだけなら、ホテルの方が選ばれやすいでしょう」）。
- 特定のサービス（AirDNA・各予約サイトなど）を紹介するときは、効果を保証しない。提携関係がなければ、その旨を書く（`airdna-revenue-simulation.html`「RIVIA&CO.はAirDNA社と提携関係はありません」）。
- 売却・解体・賃貸など、宿以外の選択肢を不当に下げない（philosophy.md 4章）。

## 6. 投資・営業の行き過ぎ

- 投資を急がせない。リスク（収益の変動、稼働率の低下、立ち上がり期間）を必ず書く。
- 「不労所得」「放っておいても稼げる」と書かない。
- 料金・手数料・プランの金額は「イメージ・個別提案が前提」（site-spec 3章）。記事で金額を断定しない。書く場合はサービスページの表記をそのまま使い、「詳しくはご相談ください」とする。
- 相談への誘導は記事の最後に一度。本文の途中で何度も売り込まない。RIVIA の方針は「無理な営業は一切なし」（`contact.html`）。

## 7. サイトの方針から来る NG（site-spec より）

| NG | 根拠 |
|---|---|
| 記事から SNS アカウント（会社・代表個人）へ誘導する、SNS のリンクを貼る | site-spec 1章 除外要素「SNSへのリンク」、4章「代表個人のSNSリンクは現在掲載しない（会社のSNSも載せない）」 |
| セミナー・イベントの告知を書く | site-spec 1章 除外要素「Seminar & Event」 |
| 「暮らす旅の手帖」を「マガジン」と呼ぶ | site-spec 1章 除外要素「マガジン」。呼び方は「暮らす旅の手帖」「記事」「メディア」 |
| 絵文字、「！」の多用、装飾的な記号、あおり見出し | site-spec 1章 トーン＆マナー（白基調・モダン・ミニマル、上品）。記事本文の「！」は既存28記事で 0 件 |
| 公開日を過去にさかのぼって付ける | `CLAUDE.md` 絶対のルール5、site-spec 5-2「公開日より前の日付を付けることはしない」 |
| 既存ページの URL・タイトルを変える | `CLAUDE.md` 絶対のルール5 |
| GA4・Clarity のタグを消す | `CLAUDE.md` |

## 8. 言葉づかい

- 「あなた」「皆さん」で呼びかけない（`voice.md`）。
- 本文で「田舎」と書かない（「地方」）。お客様の声の引用の中だけは可。
- ゲスト・旅行者の国籍や属性で決めつける書き方をしない（例: 「〇〇人はマナーが悪い」）。文化の違いは「事前に分かりやすく伝える」視点で書く（`guest-review-tips.html`）。
- 地域・空き家・所有者を否定する言い方（「お荷物」「負の遺産」「ゴミ屋敷」など）をしない。RIVIA にとって空き家は「地域に眠る価値」（philosophy.md）。
- 法令用語を誤用しない（「空家」は法令名・法令用語のみ。それ以外は「空き家」。`glossary.md`）。

## 9. 既存ページで、記事にそのまま転用しない表現（人の確認待ち）

サイト上にあるが、記事の基準（断定しすぎない）から見ると強めの表現。ページの修正はブランド学習係の担当外なので、ここに記録だけしておく。

| 表現 | 場所 | 気になる点 |
|---|---|---|
| 「解体せず宿泊施設として活用すれば、解体コストゼロで逆に収益を生む資産に変えられる可能性が高いです。」 | `service-operation.html` FAQ | 「可能性が高い」は根拠を示しにくい。記事では「〜可能性があります」まで |
| 「販売しにくかった物件も、民泊としての利回りを示すことで売れる商品になります」 | `service-partnership.html` しくみ図の注記 | 結果を断定している |
| 「初期費用0円で、毎月決まった家賃を受け取る」 | `service-operation.html` おまかせ固定家賃プラン | 条件つき（プランのイメージ）。記事で使うときは「プラン例」であることと個別提案が前提であることを添える |
| 「その価値を求める国内外の旅行者に確実に届けます。」 | `about.html` Vision 03 | ビジョンのコピーとしては可。記事の本文で集客効果を「確実」と書くのは不可 |

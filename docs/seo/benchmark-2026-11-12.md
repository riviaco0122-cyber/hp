## 3本に共通していた作り

**冒頭**
- パンくず → 記事の種類のラベル（ノウハウ／調査レポート／主張）→ タイトル → 著者・公開日・更新日 → アイキャッチ（タイトルの文字と著者の顔）→ 3〜5行のリード。
- リードは「読み手の悩み → なぜいま問題か → この記事で何が分かるか」の3段。
- 調査レポートは、目次の前に「この記事のまとめ」を置く。調査で分かったことを1項目1〜2文・数字入りで並べ、**各項目の末尾に、その答えが載っている節へのリンク（Q1〜Q6）**を付けている。AI に引用されやすく、読み手は気になる所へすぐ飛べる。

**本文**
- 見出しは、読み手の問いそのもの（調査レポートは設問をそのまま H2 にしている）。
- 小見出しが3つ以上ある節は、節の入口に「＜〇〇のポイント＞」の囲みを置き、小見出しを3〜5個並べる（**節の中の目次**。各項目が小見出しへのリンク）。
- 段落は1〜2文ごとに改行し、太字は「その段落で言いたい1文」だけ。
- 図は「データ1つにつき1枚」。図の中に「調査名｜年月」と自社のロゴが入っている。他社の図を使うときは、図の下に「◯◯『題名』より引用」とリンクを付ける。
- 数字は「数字 → 読み取れること → **この調査では言えないこと** → 読み手への示唆」の順で書く（例：「頻度の変化と AI 検索の関係は、今回の調査だけでは分からない」と自分で限界を書いている）。
- 自社の実践を数字で書く（メールの配信回数、配信時間ごとの反応、マーケ部門の人数、動画は外注していること）。一次情報であり、読み手にとっては「この会社も同じ悩みを持っている」という安心になる。
- 調査レポートは、最初の節が「調査概要」（期間・方法・対象・人数）。
- 主張の記事は、世の中で言われていることに対して自社の立場をはっきり書き、自社の調査と外部の調査で裏づけ、考え方を1枚の概念図で見せる。

**導線**
- 本文の途中、話題が出た直後に「詳しくはこの記事をチェック！」の**関連記事カード**（題名＋2行の要約）を置く。
- 相談の案内は、その節の話題に合うものを節の直後に置く（資料の話の直後に、資料作成サービスの案内）。最後に大きな相談の箱。
- 最後に、著者と編集者のプロフィール（経歴・担当）、関連記事、新着記事。
- 「目次に戻る」ボタンが、画面の右下にずっと出ている。

## 人が「見やすい」と言った3点（人の評価 2026-11-12）

**① 図形・グラフの種類が多い**
- 使われていた図：円グラフ（割合）、横棒グラフ（理由・段階の順位。上位2つだけ色を変える）、**2時点を並べた横棒**（2025年3月と10月の比較）、場面のイラストを3枚並べた図（時間帯ごとの行動）、2つの言葉を色違いの箱で対にした図（GIVE／TAKE）、考え方を1枚で見せる概念図、検索画面のスクリーンショットに**赤い枠と矢印で注目点を示した図**、リンク先の記事のサムネイル。
- どの図も、**図の上に問い（「Q：以前と比べて〜変わりましたか？」）、図の下に出典と時点**。図だけ切り出されても意味が通る。
- アキヤドの図は6種類（比較・流れ・循環・式・棒・要点。`tools/figures.py`）。足りないのは、**割合の円グラフ、2時点の比較の棒、画面の写真に枠と矢印を付けた図、対の言葉の図**。棒グラフで上位だけ色を変える形は、`bars(top=…)` で作れる。

**② 改行が自然**
- 本文は**左揃えで行末まで詰め、文が終わったら（「。」で）改行して次の文を新しい行から始める**。段落は1〜3文。言葉の途中で行が折れる所もあるが、1文ごとに行頭がそろうので、読みにくさを感じない。
- 見出し・図の中の文字は短く、1〜2行に収まる長さで書かれている（改行の位置を細かく調整しているのではなく、**短く書くことで自然に見せている**）。
- アキヤドへの示唆：改行の見た目は、仕組みを細かくするより「1文ごとに改行する」「文を短くする」の2つで大部分が決まる。改行の仕組みの一本化（`design-guide.md` 3章）は、この形を基本にする案で人に確認する。
- ただし、ボタンの中の文字は「（無／料）」のように折れていた。ボタン・ラベルは折らない（アキヤドはここを守る）。

**③ CTA ボタンの位置**
- 置き場所は4か所：①リードの直後（資料の画像＋説明＋ボタン、その下に「無料で相談する」の文字リンク）②本文の途中、話題が合う節の直後に横長のバナー（資料作成の話のあとに資料作成サービス）③記事の最後に、悩みの箇条書き（左）＋ボタン（右）の大きな箱 ④ページの下に「無料で相談してみる／会社概要ダウンロード」の2択とメルマガ登録。
- 主のボタン1つと、軽い文字リンク1つを組にしている（気軽な行動と、本気の行動の2段）。
- アキヤドとの違い：①（要点の直後の相談の案内）と③（記事の最後）に相当するものはある。②（話題に合う節の直後の案内）はない。記事の中の案内は「相談」が中心で、主のボタンの隣に軽い行動（資料請求など）を並べる形にはなっていない。

## アキヤドと比べて

宿泊税の記事（`accommodation-tax`）で確かめた。

| 作り | アキヤド | やること |
|---|---|---|
| 冒頭の要点 | ある（「この記事のポイント」） | **各項目に、その答えが載っている節へのリンクを付ける** |
| 問いの見出し | ある | そのまま |
| 著者・監修・公開日・更新日 | ある | そのまま |
| 節の中の目次 | ない | 小見出しが3つ以上ある節の入口に、自動で付ける |
| 図の出典・時点 | 図の下の表示がない（figcaption 0件。出典は記事の最後にまとめてある） | 数字を使う図に「出典｜時点」を1行付ける |
| 本文の途中の関連記事 | 文中リンクだけ（この記事で2本） | 関連記事カード（題名＋短い要約）の部品を作り、話題が出た直後に置く |
| 節ごとの相談の案内 | 要点の直後に1つと、記事の最後 | 話題が合う節の直後にも置けるようにする（1記事に2つまで） |
| 目次に戻る | ない（目次は冒頭の折りたたみだけ） | スマホで右下に小さく出す |
| 数字の限界を書く | 記事による | 品質管理部の確認項目にする（「この数字で言えないこと」を1文） |
| 記事の種類 | ない | 「運営記録から（自社の数字）」「アキヤドの考え（主張）」の型を足すか、人と相談する |

## 取り入れないこと
- 本文の上に重なる、浮いた広告の枠（右下の案内が本文を隠していた）。
- 1ページに相談・資料・人材・セミナーの案内を5つ以上並べる。
- ボタンの文言が途中で改行される形（「（無／料）」「ダウンロー／ド」）。アキヤドの改行の決まりで防いでいる形なので、まねしない。
- 太字の文が何行も続く段落（太字は1段落1文まで）。

## 取り入れる順番（案）
1. 要点の各項目に、節へのリンクを付ける（作りの変更だけで全記事に効く）
2. 「目次に戻る」ボタン
3. 図に出典と時点を付ける（`tools/figures.py`）
4. 本文の途中の関連記事カード（部品を作り、記事データで使う）
5. 節の中の目次（小見出し3つ以上の節）
6. 記事の種類（調査・主張）を足すか（企画の話なので人と決める）

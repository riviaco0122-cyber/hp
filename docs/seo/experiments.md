# 改善施策の台帳（SEO/AIO の PDCA）

サイトに加えた改善（title の書き直し、内部リンク、新規記事など）を 1 件ずつ記録し、**実施前後の 28 日を同じ指標で比べて効果を判定する**ための台帳。人も AI社員も読み書きする。数値の取得・判定・書き込みは `tools/pdca.py` が行う。

- 計画を足す: `python3 tools/pdca.py new --page /media/xxx.html --type "title・description" --metric CTR --target 2.0%`（ID を自動で振る。仮説・変更内容・副指標は手で書く）
- 実施前にベースラインを取る: `python3 tools/pdca.py baseline E-YYYYMMDD-01`
- PR がマージされて公開されたら: 「状態」を `実施済み`、「実施日」をマージ（公開）した日にする。「測定日」は空でよい（`check` が実施日＋28日を入れる）
- 測定日を迎えたら: `python3 tools/pdca.py check`（前後 28 日を比べ、結果・全体の変化・判定・判定の理由を書き込む）
- 状況の一覧: `python3 tools/pdca.py report`（台帳だけ読むので環境変数なしで動く）
- 判定済みになったら、学びを [learnings.md](learnings.md) に書く

## 書き方のルール

- 1 施策 ＝ `### E-YYYYMMDD-連番 短い名前` の見出し＋決まった項目の箇条書き（`- 項目: 値`、1 行で書く）。項目の名前と順番は変えない（`tools/pdca.py` が機械的に読み書きする）。
- 施策は、下の「施策一覧」にある開始と終了のコメント行（pdca:start と pdca:end）の間に置く。その外（この説明・書式見本・記入例）はツールが読まない。
- ID: `E-` ＋ 計画した日（日本時間）＋ `-` ＋ その日の連番 2 桁（例 `E-20261012-01`）。一度振った ID は変えない。
- **状態**: `計画` → `実施済み`（マージ・公開された）→ `測定中`（check が自動で変える）→ `判定済み`
- **施策の種類**: `title・description`／`本文の書き直し`／`内部リンク`／`新規記事`／`構造化データ・AIO`／`技術`
- **対象ページ**: 公開URLのパス（例 `/media/akiya-minpaku.html`）。末尾を `/` にすると配下すべて（例 `/media/`）。`サイト全体` も可。
- **仮説**: 「〜すれば、〜が〜になる。なぜなら〜」の形で書く。
- **主指標**（1つ）・**副指標**（読点区切りで複数可）に使える名前:

  | 名前 | 中身 | 母数（データ不足の判定に使う） |
  |---|---|---|
  | CTR／クリック／表示回数／掲載順位 | Search Console（掲載順位は小さいほど良い） | 表示回数 各期間 100 以上 |
  | ページビュー／セッション／エンゲージメント率／平均エンゲージメント時間／相談ボタンのクリック | GA4（そのページを含むセッション基準。相談ボタンのクリックは `cta_click` の件数） | セッション 各期間 30 以上 |
  | 入口セッション／相談／相談件数／相談率／サービス移動／サービス移動率／AI検索流入 | GA4（そのページを入口にしたセッション基準。相談＝`generate_lead` に至ったセッション、サービス移動＝service-*.html・contact.html も見たセッション） | 入口セッション 各期間 30 以上 |

- **目標値**: 主指標の目標。`2.0%`、`1.2%→2.0%`（矢印の後ろを使う）、`8位`、`90秒`、`+20%`（符号つきは変更前からの相対）。
- **ベースライン**: `baseline` が書く（変更前 28 日の値と期間）。
- **実施日**: マージされて公開された日（予約公開の記事は公開日）。**測定日**: 実施日＋28 日（データ不足で延長されると 28 日ずつ伸びる）。
- **結果・全体の変化・判定・判定の理由**: `check` が書く。人が手で直すときは「判定の理由」に理由を書き足す。
- **判定**: `効果あり`／`一部効果`／`効果なし`／`悪化`／`保留`（データ不足。測定日を延長）／`判定不能`（3 回延長してもデータ不足）
- **次の一手**: 判定を受けて次にやること（続ける・広げる・戻す・別の仮説）。**関連PR**: PR の URL。

### 判定のルール（`tools/pdca.py` の定数）

- 比較期間: 実施日の前 N 日と後 N 日（実施日当日は除く。N ＝ 測定日 − 実施日、はじめは 28）。`check` は測定日＋3 日以降に行う（Search Console の確定待ち）。
- データ不足（主指標の母数が前後どちらかで下限未満）→ `保留`、測定日を 28 日延長。延長は最大 3 回、その後もデータ不足なら `判定不能`。
- 主指標が目標値に届き、改善し、サイト全体の同じ期間の変化を上回る → `効果あり`
- 目標値に届いたが全体の変化を上回らない、または目標未達でも +10% を超えて改善し全体を上回る → `一部効果`
- 変化が ±10% 以内、または全体並みの改善・低下 → `効果なし`
- −10% を超えて悪化し、全体の変化より悪い → `悪化`

## 記入例（ダミー。実在の施策・数値ではない）

```
### E-20000101-01 【ダミー】民泊の始め方の title に費用の数字を入れる
- 状態: 判定済み
- 対象ページ: /media/example-dummy.html
- 仮説: title に「費用◯万円〜」の数字を入れれば、検索結果での CTR が 1.2% から 2.0% になる。なぜなら、この記事の主なクエリは費用を知りたい人が多く、数字があると答えがあると分かるから
- 施策の種類: title・description
- 変更内容: title を「民泊の始め方」→「民泊の始め方｜費用の目安と手続き7ステップ」に変更（description も同じ趣旨に）
- 主指標: CTR
- 目標値: 1.2%→2.0%
- 副指標: クリック、掲載順位
- ベースライン: CTR 1.20%（表示回数 1500）／副指標: クリック 18、掲載順位 9.4位／期間 1999-12-04〜1999-12-31（28 日、2000-01-01 取得）
- 実施日: 2000-01-01
- 測定日: 2000-01-29
- 延長回数: 0
- 結果: CTR 1.20%→2.10%（+75.0%）／母数 表示回数 1500→1600／副指標: クリック 18→34（+88.9%）、掲載順位 9.4位→9.1位（+3.2%）／比較期間 前 1999-12-04〜1999-12-31・後 2000-01-02〜2000-01-29（各 28 日、実施日当日を除く）
- 全体の変化: サイト全体 CTR 1.00%→1.05%（+5.0%）／対象ページは全体を上回る
- 判定: 効果あり
- 判定の理由: CTR 1.20%→2.10%（+75.0%）／サイト全体 +5.0%。目標 2.00%に到達し、全体の変化を上回った（2000-02-01 判定）
- 次の一手: 同じ「費用」系のクエリが多い記事 3 本にも数字入りの title を試す
- 関連PR: https://github.com/（ダミー）
```

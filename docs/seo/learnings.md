# 改善施策から得た学び

[experiments.md](experiments.md) で **判定済み** になった施策から、次の施策に使える学びを残す。企画・マーケ部が判定のたびに追記し、構成案・キーワード選定・title の案を作るときに読む。

- **同じ傾向の施策が 2 件以上「効果あり」になったら、`docs/seo/playbook.md` のルールに昇格させる**（昇格は PR の「人の確認が必要な点」に挙げる）。昇格したら、その学びの「状態」を `playbook に昇格` にし、playbook の該当箇所を書く。
- 「効果なし」「悪化」からの学び（やっても効かなかったこと）も書く。同じ失敗を繰り返さないため。
- 1 件だけの結果は「仮の学び」。データ不足（保留・判定不能）の施策は根拠にしない。
- 根拠の施策 ID を必ず書く。数値は experiments.md の「結果」から写し、作らない。
- 季節要因に注意: サイト全体の変化を上回っていない結果（「一部効果（全体並み）」）は根拠を弱いと書く。

## 書式

```
### L-YYYYMMDD-01 学びを1文で（例: ◯◯な記事では、title に数字を入れると CTR が上がる）
- 状態: 仮の学び／確かめ中／playbook に昇格／否定された
- 根拠の施策: E-…（効果あり）、E-…（一部効果）
- 対象: どんな記事・ページ・クエリに当てはまるか
- 内容: 何をして、どの指標がどれだけ変わったか（experiments.md の結果から）
- 当てはまらなかった例: E-…（効果なし）など
- 次に確かめること:
- playbook: 昇格した章・節（未昇格なら空）
```

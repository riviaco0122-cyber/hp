## 5. サービスページ（全5ページ共通構造）

**構成:** ページ見出し → サービス概要 → 社会的背景と市場データ → こんなお悩みはありませんか？（経営課題と打ち手） → RIVIAのご支援内容 → 運営実績 → 相談CTA → よくあるご質問 → そのほかのサービス

### 共通のデザイン指定

1. **ページ見出し:** サービス名、トップメッセージ（明朝体・大）、「こんな方へ」（トップのお悩み文と同じ）、ボタン2つ（「無料で相談する」「お悩みと解決策を見る」）。写真は使わない。
2. **社会的背景と市場データ:** 導入文「いま、この市場で何が起きているのか。3つのデータから整理します。」の下に、3枚のカードを横並び（スマホは縦並び）。各カードは上から次の順で表示する。
    * 番号（01〜03）と「何の数字か」（ラベル）
    * 数字（極細の大きな欧文数字。キーワード型は明朝体）
    * 一言でいうと（見出し）
    * 解説文
    * 「〇〇にとっては」（読み手にとっての意味。グレー背景で区切る）
    * 出典（確認できたもののみ）
    * カードの下に「つまり」のまとめを置き、「具体的なお悩みと解決策を見る」リンクで次のセクションへつなぐ。
3. **こんなお悩みはありませんか？:** 表面的な悩みではなく経営課題として整理する。**全サービス4件ずつ**。1件ごとに、左に「経営課題」（線画アイコン＋見出し）と「現場で起きていること」（お客様の声）、右に「RIVIAの打ち手」「改善する経営指標」（タグ）「この課題について相談する」リンク（ご相談カテゴリを自動選択してお問い合わせへ）を置き、矢印でつなぐ。

2. **想定利回りの根拠を示せない**

4. **許認可や改修の要否がわからない**
    * 現場で起きていること: 宿泊施設として使えるのか、どこまで改修が必要なのかが分からず、販売前の整備に踏み切れない。

    * 改善する経営指標: 許認可取得の確実性 ／ 改修費用 ／ 開業までの期間

**RIVIAのご支援内容（タイムライン）**

3. **施設の魅力がWEB上で伝わらず、指名されない**
    * 現場で起きていること: 自社HPが古いまま。検索しても地図でも見つけてもらえず、宿の良さが伝わっていない。
    * RIVIAの打ち手: 自社HPやSEO、Googleマップを整え、「探したときに見つかる」状態をつくります。 写真・動画・記事・SNSで世界観を一貫して伝え、施設名で指名される宿にします。
    * 改善する経営指標: 指名検索数 ／ 自然検索からの流入 ／ 自社サイトの予約率
4. **集客投資の費用対効果が見えない**
    * 現場で起きていること: 広告や制作にお金をかけても、売上につながったか分からず、次の判断ができない。

* **トップメッセージ:** 地域の未来を創る、最適な人材と出会うために。

    * 現場で起きていること: 人が足りず、客室やサービスを絞っている。新しい事業の話があっても踏み出せない。

    * 現場で起きていること: 求人サイトに50万円以上払ったのに、応募は1件でドタキャン。毎回何も残らない。
    * RIVIAの打ち手: 採用サイトを軸に、求人検索・スカウト・広告・SNSなどを最適に組み合わせます。 チャネルごとの応募数・採用数・費用を計測し、成果の出る手段に予算を集中させます。
    * 改善する経営指標: 採用単価 ／ チャネル別の採用数 ／ 媒体費用
3. **「選ばれる理由」がなく、条件競争で負けている**
    * 現場で起きていること: 「田舎だから」「無名だから」と諦めている。給与や休日では大手に勝てない。

    * 改善する経営指標: 応募数 ／ 求める人材の応募比率 ／ 内定承諾率
4. **採用しても定着せず、投資が回収できない**
    * 現場で起きていること: 採用しても「思っていた仕事と違う」と数ヶ月で辞めてしまい、費用と時間が無駄になる。
    * RIVIAの打ち手: 仕事の実像を入社前に伝え、選考基準とカジュアル面談を設計してミスマッチを防ぎます。 入社後のフォロー体制を整え、定着し活躍できる状態をつくります。
    * 改善する経営指標: 早期離職率 ／ 定着率 ／ 採用・教育コストの回収

## 5-2. RIVIA MEDIA（media.html ／ media/*.html・追加）

### 目的
* 空き家オーナー・宿の開業検討者・観光事業者が検索する悩みに答え、サービスページとお問い合わせへつなげる。
* SEO（検索エンジン）と AIO（AIによる検索回答・要約）の両方で引用されやすい構成にする。

### 記事一覧（media.html）
* 見出し「RIVIA MEDIA ｜ すべての記事一覧」、カテゴリの絞り込みボタン（すべて / 空き家活用 / 観光市場 / 地方創生 / 開業・制度 / 収益・運営）。
* 記事カード（サムネイル・カテゴリ・タイトル・公開日）を3列で表示。6件を超えたら「もっと記事を見てみる ＋」で追加表示。
* サムネイルは記事ごとの写真（images/photos/thumb/ の軽量版）。記事トップは原寸の写真を使い、OGP画像にも同じ写真を設定する。割り当ては build 内の ARTICLE_PHOTOS。
* 写真の配置：TOPヒーロー（素材⑧・暗めのグラデーションを重ねて白文字）、相談CTA（全ページ共通）、各サービスページTOPの背景写真、代表者の顔写真。写真は原寸のまま格納し再圧縮しない。
* トップページ（運営実績の下）と、各サービスページ（よくある質問の下）にも関連記事を3件まで表示する。

### 記事ページの構成（SEO・AIO対策）
1. カテゴリ・タイトル（検索されるキーワードを前半に）・公開日・更新日・読了目安・執筆者
2. リード文（meta description と同じ要約）
3. **この記事のポイント**：結論を3〜5行の箇条書きで先に示す（AIの要約・引用に使われやすい）
4. 目次（ページ内リンク）
5. 本文：見出しは検索される疑問文・結論型にし、表・手順リストで整理。数値には必ず出典を明記
6. よくある質問（FAQ。構造化データ FAQPage を設定）
7. 参考資料（公的機関の資料名）と「公開日時点の情報」である旨の注記
8. 執筆者情報（E-E-A-T。監修者を立てる場合はここに追加）
9. 関連サービスへのリンクと相談ボタン、あわせて読みたい記事
* 構造化データ: Article ／ FAQPage ／ BreadcrumbList。sitemap.xml に全記事を登録。

### 公開日の扱い（予約公開）
* 記事ごとに実際の公開日を設定し、公開日を迎えた記事だけを一覧・トップ・関連記事に表示する（main.js が日付を判定）。

## 仕事の進め方（この順で。飛ばさない）
1. **目的を一文にする**：だれが、どの画面で、何をしたいのか。何が伝われば成功か。
2. **参考を集める**：入っていれば UI Design Review（UXKIN）の比較で、実在の一流サイト・アプリが同じ課題をどう解いているかを見る（Mobbin は有料のため使えない）。入っていなければ、知っている一流の事例（例：エディトリアル＝Kinfolk・Casa BRUTUS、宿＝NOT A HOTEL・Airbnb、実用＝Stripe・Notion の説明ページ）から型を挙げる。見た目を写さない。
3. **方向性を2〜3案、Figma で作る**：ファイル「アキヤド 図解リデザイン」（fileKey `hjbf94FSeibQD3bPNt5XYK`）に、**PC（1440）とスマホ（390）を必ず両方**。案ごとに、書体・色・余白・写真の扱いの考え方を1行で書く。`use_figma` の前に Figma の手順書（figma-use・figma-generate-design）を読む。Figma は確認なしで使ってよい（人の方針 2026-11-26）。
4. **自分で講評する**：下の「合格の基準」で一つずつ見る。入っていれば Design プラグインの design-critique・accessibility-review も使う。直してから人に出す。
5. **進め方を決める**：内容（文言・数字・事実）が変わらないデザインの変更は、人の確認を待たずに進めてよい（人の方針 2026-11-27）。自己講評と編集長の確認を通して本番に出し、PC・スマホの画像を添えて報告する。方向性が大きく分かれるときや、内容が変わるときだけ、人に見せて選んでもらう。
6. **デザインの決まりにする**：選ばれた案を、Figma の変数（色・余白・角丸）・文字の段階・部品にまとめ、`css/style.css` の変数と `docs/design-guide.md` に写す。
7. **実装する（またはエンジニア部に渡す）**：部分ごとに足さず、決まりに沿ってまとめて直す。CSS は元のルールを直し、上書きを足さない（技術負債をためない）。
8. **確かめる**：390px と 1280px で撮って目で見る。`seo_check`・`site_check`・`line_quality`・`short_lines` を通す。

## 合格の基準（一つでも外れたら出さない）
- **一目で何のページか分かる**。見出し・主な数字・次の行動（相談・記事を読む）に、はっきりした強弱がある。
- **スマホはスマホ用に設計している**。PC の縮小で縦に長くなっていない。横に並べる・詰める・折りたたむを使い分けている。
- **文字だけが続かない**。数字・手順・比較は、図・表・カードで見せる。
- **文字の段階・余白の段階・色が、ページ全体でそろっている**。節ごとに別の決まりを作らない。
- **日本語の改行がきれい**。見出しが「選ば｜れる」のように語の途中で折れない。中央揃えの文は句読点の区切りで折る。
- **安っぽくない**。平たいクリップアート、手描きの SVG のイラスト、ありがちなテンプレートの並びを使わない。
- **事実を作らない**。図・数字・ビジュアルの説明は、本文と確認済みの資料にあるものだけ。架空の物件を「自社の物件」に見せない。公開していない金額を逆算できる形にしない。
- **だれでも使える**。文字と背景のコントラスト、押せる所の大きさ（44px 以上）、色だけに頼らない区別。

## ビジュアルの作り方
- **写真が基本**（人の方針 2026-11-27）。会社の実際の写真か、Unsplash の上質な写真（出典を `docs/photo-credits.md` に）を使う。ヒーロー・カード・特徴・記事のアイキャッチは写真で組む。
- **解説模型は、写真では説明できないときだけ**。家の中のどこに何があるか（設備の場所）、物の仕組みや順番を、番号で指して説明する図に限る。雰囲気づくりや飾りのために模型を入れない。迷ったら写真にする。
- 模型を作るとき：Figma の `generate_image`（建築模型の 3D、プロンプトの型は playbook 15-4）。文字は画像に入れず HTML で重ねる。
- AI で作った風景・建物の写真は使わない（人が見て OK を出したものを除く）。
- 数字のグラフ：画像にしない。`tools/figures.py` の部品で作る（dataviz スキルの決まり）。
- 動画（Higgsfield）は、有料プランにしないと作れない（2026-11-27 時点）。

## してはいけないこと
- 内容（文言・数字・事実）が変わる変更を、人に見せずに本番へ出す。
- PC だけ整えて、スマホを見ずに終える。
- 一部の節だけを直して、ほかの節とちぐはぐにする。
- 本番ブランチに直接 push する（全社ルール 1）。

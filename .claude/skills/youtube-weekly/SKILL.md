# 週次 YouTube サイクル（編集長の手順）

あなたは編集長です。`CLAUDE.md` のルールと `docs/youtube/manual.md`（制作マニュアル）に従い、YouTube 班（`.claude/agents/yt-*.md`）に Agent ツールで仕事を振って、**解説動画1本（8〜10分）と、そこから切り出したリール1本（縦長・45〜60秒）** を完成させ、人に届けます。YouTube への公開は人が行います（自分では公開しない）。

**部署への依頼は必ず待ってから次へ（`run_in_background: false`）。最後の要約を書くまで、1回の返答の中で最後までやり切る。** 定期実行は最初の返答が終わった時点で「完了」になり、通知もそのときに送られる。

## 0. 準備
1. 本番ブランチを調べて最新を取る（`git ls-remote --symref origin HEAD`）。作業ブランチは **`youtube/weekly`**。前回分が未マージなら、それに本番ブランチを取り込んで続ける。マージ済みなら本番ブランチから作り直す。
2. `bash tools/video/setup_voicevox.sh`（声の準備）、`python3 -m pip install -q pillow`。Playwright の Chromium は入っている（`NODE_PATH=/opt/node-tools/node_modules`）。
3. 今回の回の番号 N ＝ `tools/video/make_strategy_ep*.py` の数 ＋ 1。

## 1. 分析（`yt-analyst`）
前の動画の数字を読み、今回変えることを1〜3つに決める。鍵がなく数字が取れないときは、そのことを要約に書き、マニュアルの法則だけで進める（止まらない）。

## 2. 企画（`yt-planner`）→ 3. 台本（`yt-scriptwriter`）→ 品質（`yt-reviewer` が台本を採点）
- 台本の採点が 90 点未満・不合格の条件ありなら、指定された工程（企画／台本）に戻す。やり直しは最大3回。

## 4. 動画（`yt-video-engineer`）
- 絵を付け、自動点検（`layout_check.py`）を0件にし、コマを目で見て直す。
- **書き出しは時間がかかる**（高画質版で約1時間）。Bash の上限は10分なので、書き出しのコマンドは `run_in_background: true` で始め、**Monitor ツールの until ループで出力ファイルとログの完了を待つ**（`until grep -q "秒" <ログ>; do sleep 30; done` など）。待っている間に返答を終えない。部署に書き出しを任せる場合も同じ方法で待つよう伝える。
- 作るもの（作業用の場所＝スクラッチパッドに置く。リポジトリには入れない）:
  - `akiyado-school-ep<N>-1440p.mp4`（YouTube 用、2560×1440）
  - `akiyado-school-ep<N>-preview.mp4`（スマホ確認用、1280×720）
  - `akiyado-school-ep<N>-reel.mp4`（リール・ショート用、1080×1920、45〜60秒）
  - `ep<N>-thumbnail.png`、`ep<N>-ja.srt`（字幕）、`ep<N>-youtube.txt`（タイトル・説明欄・タグ・リールの説明文）

## 5. 最終の品質（`yt-reviewer`）
仕上がりを採点（3秒ごとのコマを全部・音声・サムネイル・説明欄）。90点未満なら戻して直し、書き出し直す。

## 6. 記録・コミット
- `docs/youtube/log.md` に、回・テーマ・長さ・採点・改善施策・リールの区間を追記。マニュアル 7 章に学びを足す。
- `bash tools/check_secrets.sh` → コミット（「YouTube 週次 YYYY-MM-DD: 第N回 〇〇」）→ `git push -u origin youtube/weekly` → 本番ブランチ向けの PR を作る（あれば説明を更新）。**マージはしない**（人が確認してマージ）。リポジトリに入れるのは台本・サムネイルのスクリプト・企画・ログ・マニュアルだけ（動画・画像は入れない）。

## 7. 人に届ける（完成版の通知）
1. **SendUserFile** で、完成したファイルを人に送る: 確認用（render）と、YouTube 用・リール・サムネイル・字幕・説明欄（attach）。
2. **PushNotification** で「今週の YouTube ができました：第N回『タイトル』（長さ）。確認用とアップロード用のファイルを送りました」と通知する。
3. 最後のメッセージ（通知メールに載る）に、短く: 今回のテーマとタイトル／長さ／採点／前回の数字と今回変えたこと／リールの区間と見出し／PR の URL／人に確認してほしいこと（読み方・事実・体験の言い回し）／アップロードの設定（子ども向け＝いいえ、改変コンテンツ＝いいえ、チャプターは説明欄のとおり、終了画面・カードなし）。
- ファイルが送れなかった場合は、その理由と、どこにあるかを書く。

## 守ること（マニュアルより、くり返し指摘されたもの）
- 画面とナレーションに省庁・機関の名前を出さない。出典は説明欄の一番下だけ。
- オープニングは動画の0秒から（幕 → ロゴ → 「アキヤド 民泊school」→ 呼び込み）。そのあと左上に今回の短いタイトル。
- 声は青山龍星（喜び）・速さ1.12。数字・「年」・「〜方」の読みは say で確かめる。両手を揺らす動き（open）は使わない。文字は中央そろえ。
- 体験は確認済みの節だけ。投資を勧めない。

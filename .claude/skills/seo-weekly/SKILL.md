# 週次 SEO/AIO サイクル（編集長の手順）

あなたは編集長です。`CLAUDE.md` のルールに従い、各部署（`.claude/agents/`）に Agent ツールで仕事を振り、結果を1つの PR にまとめます。1回で終わる量に絞ることを優先し、終わらなかったものは引き継ぎに回します。

## 0. 準備
1. 最新の main を取り込み、作業ブランチ `seo/weekly-YYYY-MM-DD` を作る（日付は日本時間の今日）。
2. `pip install -q -r tools/requirements.txt`（失敗しても続行。集客データなしで進める）。

## 1. 洗い出し（進行管理部 `pm` の仕事A）
今回の作業リスト（最大5件）を受け取る。

## 2. 情報収集（リサーチ部 `researcher`）
ネタ箱の処理と、作業リストのテーマについてのリサーチメモ作成。

## 3. 企画（企画・マーケ部 `marketer`）
集客データの分析、既存記事の改善方針、新規記事が作業リストにあれば構成案。

## 4. 制作（並行してよい）
- 新規記事・書き直し → 執筆担当 `writer` が原稿を書く → 品質管理部 `qa` が採点（差し戻しは最大3回）→ 合格したらエンジニア部 `engineer` が HTML 化・組み込み
- 技術改善・メタ情報の修正 → エンジニア部 `engineer`
- ブランド知識の見直し（月の最初の週だけ）→ ブランド学習係 `brand-learner`

## 5. 最終チェック（品質管理部 `qa`）
`git diff main` 全体を対象に採点し、「人の確認が必要な点」を出してもらう。`python3 tools/seo_check.py` のエラーが 0 であること。

## 6. 記録とPR（進行管理部 `pm` の仕事B → 編集長）
1. pm にカレンダー・ログ・ダッシュボードの更新と PR 説明の下書きを依頼する。
2. 変更をコミットし（メッセージは日本語で「週次SEO: 〜」）、push して **main 向けの PR を作成する**。PR のタイトルは「週次SEO YYYY-MM-DD: 主な変更の要約」。
3. **main へのマージはしない**（人の最終確認のため）。

## 中断の基準
- `seo_check.py` のエラーが直せない、品質管理部が3回差し戻しても合格しない → その作業は PR に含めず、ログの引き継ぎに書く。
- 何も変更がなかった回は PR を作らず、ログだけ更新してコミットする。

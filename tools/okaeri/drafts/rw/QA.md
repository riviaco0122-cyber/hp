# 品質保証部への依頼: 見せ方のリライトの採点

対象: tools/okaeri/drafts/rw/<id>.py（リライト後）。元の記事は tools/okaeri/content.py の同じ id（まだ書き換えていない＝リライト前）。

人の方針（2026-11-20）: 「ガイドブックのような固い文章はそもそも読みづらい」。playbook 3-1（とくに 6）に足した。

見ること:
1. playbook 4章のとおり 100点満点（機械40は `python3 tools/okaeri/article_score.py tools/okaeri/drafts/rw/<id>.py`、品質60）で採点し、ゲートを判定する。
2. **リライト前と比べて、事実・数値・出典・体験が変わっていないか**を、Python で元と新の両方を読み込んで比べる（数字の集合・[[s:…]] キーの集合・[[l:…]] の集合を比べ、消えた・増えたものを1つずつ確かめる）。新しく足された文が事実を言っていたら、出典があるか（ないならゲート）。意見は「we think」などで意見と分かるか。
3. **英語を母語とする読み手が、途中で引っかからずに読めるか**を、いつもより厳しく見る。ガイドブック調（1文の詰め込み、出典の前置き、事実の並べ立て、決まり文句）、直訳調、くだけ過ぎ。引っかかる文があれば、具体的に「この文 → こう直す」を出す。
4. 日本語レビュー版が自然な日本語か。

90点以上・ゲート0なら合格。合格でも、直したほうがよい文があれば一覧で出す（編集長が直す）。不合格なら、直すべき箇所を具体的に。
報告は日本語で短く: 点数（機械・品質の内訳）、ゲート、元との差で気になったもの、直したほうがよい文（原文 → 案）。ファイルは直さない。
